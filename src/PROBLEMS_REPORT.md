## ⚠️ ПРОБЛЕМЫ, НА КОТОРЫЕ НУЖНО ОБРАТИТЬ ВНИМАНИЕ

### 1. Логические проблемы (НЕ ИСПРАВЛЕНЫ, т.к. требовалось не менять логику)

#### s21_strlen (s21_string.c:4-14)
- **Проблема**: Возвращает `-1` при `NULL`, но `s21_size_t` = `size_t` (unsigned тип)
- **Местоположение**: `s21_string.c`, строка 10: `res = -1;`
- **Рекомендация**: Стандартный `strlen` не проверяет на NULL, но если нужна проверка, возвращать 0

#### s21_strncpy (s21_string.c:52-63)
- **Проблема**: Логика не соответствует стандарту - должна копировать n символов даже после '\0' и дополнять '\0' если n больше длины src
- **Местоположение**: `s21_string.c`, строки 52-63
- **Рекомендация**: Переписать согласно стандарту POSIX

#### s21_strncat (s21_string.c:66-71)
- **Проблема**: Не добавляет '\0' в конце (но по стандарту это правильно - добавляет только один '\0')
- **Местоположение**: `s21_string.c`, строки 66-71
- **Примечание**: Нужно проверить стандарт - возможно, это правильное поведение

#### s21_strcspn (s21_string.c:109-118)
- **Проблема**: Использует `s21_strlen` в цикле, что неэффективно
- **Местоположение**: `s21_string.c`, строки 113, 115
- **Рекомендация**: Вычислить длины один раз

### 2. Использование стандартных функций вместо s21_ версий

#### s21_strstr (s21_string.c:202-218)
- **Проблема**: Использует `strlen` вместо `s21_strlen`
- **Местоположение**: `s21_string.c`, строки 203-204
- **Рекомендация**: Заменить на `s21_strlen`

#### s21_strtok (s21_string.c:221-244)
- **Проблема**: Использует `strchr` вместо `s21_strchr`
- **Местоположение**: `s21_string.c`, строки 231, 236
- **Рекомендация**: Заменить на `s21_strchr`

#### s21_strerror (s21_string.c:134-143)
- **Проблема**: Использует `strncpy` и `sprintf` вместо `s21_strncpy` и `s21_sprintf`
- **Местоположение**: `s21_string.c`, строки 138, 140
- **Примечание**: Это может быть проблемой, т.к. s21_strerror используется для обработки ошибок, и использование s21_ версий может вызвать циклические зависимости

### 3. Предупреждения компилятора

- **s21_strerror**: Предупреждение `-Wstringop-truncation` (строка 138)
- **s21_strstr**: Удалена неиспользуемая переменная `result`

## 📝 ЗАМЕЧАНИЯ

1. В коде есть два определения `s21_strlen` - одно в `s21_string.c` и одно в `s21_sprintf.c` (вспомогательная функция). Это нормально, т.к. они в разных файлах.

2. Функция `s21_strerror` использует стандартные функции `strncpy` и `sprintf`. Это может быть намеренным решением для избежания циклических зависимостей.

3. Функции используют `s21_size_t` и `s21_NULL`, которые теперь определены в `s21_string.h`.
